# TCRT5000 扫描法识别数字 0–9 —— 可行性测试报告

> 关联任务书：[`docs/Question.md`](Question.md)（基于 STM32G0B1 及红外对射传感器的文字识别器）
> 数据与工具：`datasets/{0..9}_scan/*.csv`、`tools/preprocess.py`、`tools/train_digit.py`
> 产物目录：`outputs/`（模型、训练过程数据、曲线、混淆矩阵、汇总 JSON）

---

## 1. 测试目的

回答一个问题：**用 8 路 TCRT5000 红外反射传感器直线排列、人工匀速扫描 6cm×6cm 纸片数字，把扫描数据交给 PC 端 PyTorch 神经网络，能否可靠识别数字 0~9？** 即验证"传感器扫描 → PC 识别"这条路是否可行，为后续设计报告与单片机端推理提供依据。

本阶段**不涉及**嵌入式 C/C++ 代码修改，只做数据侧的训练可行性验证。

> 进展说明：第一轮先采集数字 0~4（100 个样本）验证管线可行（5 类测试均值 80.0%±7.3%），随后补齐 5~9，本报告为**全量 10 个数字**的最终结果。

## 2. 数据集情况

- 来源：`scan_view.py` 采集，人工手持纸片在传感器上方匀速滑过，每扫一个数字保存为一个 CSV（8 通道 ADC 原始值，0–4095）。
- 规模：数字 **0~9** 各 **20 个文件**，共 **200 个样本**；每个文件 = 一张独立纸片的一次扫描（无同纸片重复扫描，按文件划分不存在数据泄漏）。
- 原始极性：**白纸 = 低值（~250），黑墨 = 高值（~3400–4095）**，无纸时全部通道恢复 ~4095。
- 人工扫描不统一的具体表现（已统计核实）：
  | 问题 | 实测情况 |
  | --- | --- |
  | 行数（Y 分辨率）不统一 | 22 ~ 118 行不等（扫描快慢不同） |
  | 黑边/纸边伪影 | **135/200** 个文件首/尾存在"含无纸电平（≈4095）通道"的行，共裁剪 **513 行**；其中包含大量**不完整黑边**（同一行左侧无纸、右侧仍是纸面） |
  | 墨量强弱不均 | 部分样本墨值偏低（弱笔画，如 `1-10.csv` 最大仅 ~3358） |
  | 整体明暗差异 | 各样本均值差异大（扫描距离抖动） |

## 3. 数据划分（14 + 3 + 3）

- 规则：每类 20 个文件，按固定随机种子（默认 **42**）洗牌后，**前 14 个 = 训练集、中间 3 个 = 验证集、最后 3 个 = 测试集**，即 **140 / 30 / 30**。
- 划分清单保存于 `outputs/split_seed42.json`，同一种子可完全复现。
- 测试集只在全部训练与调参完成后做**一次**最终评估，不参与早停选择（早停用验证集）。

## 4. 预处理（应对"不统一 + 黑边"）

`tools/preprocess.py` 三步处理，全部**逐样本**进行（不使用全局统计，避免把测试集信息带入训练）：

1. **黑边/楔形黑边裁剪（v2）**：一行中**任一通道 ≥ 4095−100（无纸电平）**即判定为含无纸的行，从首/尾**严格连续**裁剪。
   - 旧规则只裁"≥6/8 通道高值"的行，会漏掉**不完整黑边**——纸边斜着进入/离开传感器视野时，同一行左侧几路无纸（≈4095）、右侧仍是纸面（低值），形成"半黑半白"的楔形行（第一轮 100 个样本中漏检 87 行）；
   - 已在全部 200 个 CSV 上验证：新规则裁剪 **513 行 / 135 个文件**，裁剪后保留区**无纸行残留 = 0、误裁纯纸行 = 0**（真实笔画的深墨行一般 3400~3900，极少达到 4095，不会误伤）；
2. **Y 向重采样**：线性插值到固定高度 **32 行**（X 保持 8 通道），消除扫描快慢造成的行数差异；
3. **逐样本归一化**：裁剪 [p1, p99] 后 min-max 到 [0,1]，吸收扫描距离造成的整体明暗差异；保持"墨 = 高值"极性。

预处理后所有样本均为 `(32, 8)`、值域 [0,1] 的浮点张量（见 `outputs/preprocess_grid.png` 预览）。

## 5. 数据增强（仅训练集，在线随机）

人工扫描不统一是本任务的主要难点，训练时对每个样本随机施加：

| 增强 | 范围 | 模拟的真实因素 |
| --- | --- | --- |
| Y 向拉伸 | 0.8 ~ 1.25 倍 | 扫描速度快慢 |
| X 向平移 | ±1 通道（边缘填充） | 纸片横向错位 |
| 幅度增益 | 0.9 ~ 1.1 | 扫描距离抖动 |
| 高斯噪声 | σ≈0.02（归一化后尺度） | 传感器/环境噪声 |

不做水平翻转（数字不对称，翻转会改变类别语义）。

## 6. 模型

微型 2D CNN（`tools/train_digit.py` 的 `TinyCNN`），输入 `1×32×8`：

```
Conv(1→8, 3×3, pad1) + ReLU
Conv(8→16, 3×3, pad1) + ReLU → MaxPool(2)
Conv(16→32, 3×3, pad1) + ReLU → MaxPool(2)
Flatten(512) → FC(512→32) + ReLU + Dropout(0.3) → FC(32→10)
```

- 参数量约 **2.3 万**（小到后续可考虑部署 STM32G0B1）；
- CrossEntropy + Adam(lr=1e-3)、batch=16、上限 300 epoch、**早停 patience=40（看验证集准确率）**；
- 训练/验证/测试完全 CPU 可跑。

### 7.3 稳健性验证（5 个不同 seed 重复实验，增强配置）

由于 30 个测试样本的准确率粒度仍较粗（1/30≈3.3%），用 5 个不同划分种子（42 / 1042 / 2042 / 3042 / 4042）重复实验，得到测试集准确率：

- 各次：**73.3% / 73.3% / 86.7% / 86.7% / 86.7%**
- **mean ± std = 81.3% ± 6.5%**（增强配置；基线 LS=0/WD=0 为 75.3% ± 4.0%，见 §7.5）

### 7.4 预处理改进回顾（黑边裁剪 v1 → v2，第一轮 0~4 数据上验证）

针对复查发现的"**不完整黑边**"（纸边斜入/斜出时，同一行左侧无纸≈4095、右侧仍是纸面，形成半黑半白楔形行）改进了黑边裁剪，改进效果在 5 类数据上验证如下：

| 指标 | 旧规则（≥6/8 通道≥3500） | 新规则（含无纸电平通道即裁，v2） |
| --- | --- | --- |
| 裁剪行数（100 样本） | 127 行 / 55 文件 | 214 行 / 56 文件 |
| 漏检的不完整黑边行 | **87 行** | 0 |
| 误裁纯纸/真实笔画行 | 0 | 0 |
| 裁剪后保留区无纸行残留 | 有 | **0** |
| 5 划分测试均值（5 类） | 77.3% ± 6.8% | **80.0% ± 7.3%** |

v2 规则已直接复用于 10 位数字的全部 200 个样本（§4），验证结果同样为"保留区无纸残留 0、误裁 0"。

### 7.5 质量增强实验（Label Smoothing / weight decay / 多 seed 投票）

在最终数据上做了三轮受控实验（`tools/train_digit.py` 新增 `--label-smoothing / --weight-decay / --ensemble`）：

| 实验 | 配置 | 测试准确率 |
| --- | --- | --- |
| A 基线 | LS=0, WD=0，5 划分 | 75.3% ± 4.0% |
| B 增强 | LS=0.1, WD=1e-4，5 划分 | **81.3% ± 6.5%（+6.0pp）** |
| C 集成 | B 配置 + 5 个 seed（主划分） | 单模型 80.0% ± 8.7 → **多数投票 83.3%（+3.3pp）** |

- **Label Smoothing + weight decay 是训练期特性，零推理/部署成本**，直接提升 6 个百分点，已成为默认配置；
- **多数投票**把主划分的单模型均值从 80.0% 提到 83.3%；投票仅用于 **PC 端识别演示**（无资源限制）；
- **MCU 部署模型**：从 5 个 seed 中按**验证集最优**选出单个模型（`model_best.pt`，无测试泄漏，主划分测试 76.7%）。跨随机初始化直接做权重平均会因卷积核置换对称性失效（实测全部预测为同一类），故不采用。

### 7.6 部署分析（STM32G0B1RBT6 + STM32Cube.AI Studio）

- 目标硬件：STM32G0B1RBT6 = **Cortex-M0+ @64MHz（无 FPU）、128KB Flash、144KB SRAM**；
- 模型已导出 `outputs/model.onnx`（输入 1×1×32×8，算子仅 **Conv/Gemm/MaxPool/Relu/Flatten**，全部受 STM32Cube.AI 支持，已用 onnx 校验通过）；
- 资源预算（2.26 万参数）：

  | 项 | fp32 | int8 |
  | --- | --- | --- |
  | 权重 | ≈88.4KB | ≈22.1KB |
  | 激活峰值 | ≈16KB | ≈4KB |
  | 结论 | Flash 偏紧（+Cube.AI 运行时） | **推荐**（Flash 富余，SRAM 充足） |

- 计划流程（未来计划，不属本阶段）：PyTorch → ONNX → **STM32Cube.AI Studio**（[ST Edge AI Suite](https://blog.st.com/stm32cube-ai-studio/)）导入 → int8 量化与校验 → 生成 C → CubeMX 集成 → 板载测试（串口收数 → 预处理 → 推理 → LED 数码管显示）；
- 注意：MCU 推理前需把"黑边裁剪 → 重采样 32 行 → 归一化"移植为 C，或先由 PC 完成预处理、串口只上传 32×8 数组（P2 演示先走后者）。

## 8. 结论：扫描方案是否可行

**判定：[基本可行，需改进]**

> 测试准确率 70~90%：方法本身有效，10 类全部可区分，但受人工扫描不统一影响，建议增加数据量、固定扫描距离/速度。

支持结论的要点：

1. **能训练、能收敛**：每类 14 个训练样本 + 在线增强 + Label Smoothing/weight decay 即可把微型 CNN 训练到高验证准确率，10 类任务同样收敛，说明 8 通道扫描图像携带了足够的数字形状信息，**传感器阵列 + PC 识别这一路线成立**；
2. **对"不统一/黑边"鲁棒**：黑边裁剪 v2 + 重采样 + 逐样本归一化有效（200 样本保留区无纸残留 0、误裁 0）；增强配置下 5 个划分测试准确率 73.3%~86.7%（均值 81.3%，标准差 6.5%），说明结果不是靠某一特定划分碰运气；
3. **质量增强有效**：Label Smoothing + weight decay 提升 +6.0pp（75.3→81.3%），多 seed 投票再 +3.3pp（PC 端用）；训练期特性对 MCU 部署零成本；
4. **主要短板是数据量与分辨率**：每类仅 20 个样本、测试集每类仅 3 个，个别难样本（弱墨、歪斜、相似笔画）会明显影响指标；8 通道 × 32 行的低分辨率下 **1↔8/9、3↔9、5↔8、6↔2/9、8↔9** 这类形状相近数字最容易混淆；
5. 对任务书评分而言，当前结果已足以支撑 **"在 PC 上利用自行编写的算法实现文字识别"（5 分项）**；测试过程与数据（3 分项）也已具备素材；单片机端可经 STM32Cube.AI Studio 部署（§7.6，P2 可选）。

## 9. 后续改进建议

- **已落地**（本报告 §7.5）：Label Smoothing + weight decay（默认开启）+ 多 seed 投票（`--ensemble`）已并入 `tools/train_digit.py`；ONNX 导出与部署内存分析（§7.6）已具备。
- **硬件/采集侧**（提高数据质量，优先级最高）：
  1. 加固定距离垫片/滑轨，消除扫描距离抖动与黑边伪影；
  2. 慢速、匀速扫描，提高 Y 向分辨率与一致性；
  3. 扩充每类到 50+ 样本，覆盖不同书写风格、速度、方向。
- **算法侧**：
  1. 目标识别率若需 ≥90%：先用"固定距离 + 更多数据"把采集质量提上去，再用本脚本复测（`--repeats 5` 直接给出均值±方差）；
  2. 用全部数据（含测试集）重训后进入"PC 实时识别演示"环节（任务书 P1）；
  3. 单片机端按 §7.6 流程经 STM32Cube.AI Studio 做 int8 量化部署（任务书 P2 可选，G0B1 128KB Flash/144KB SRAM 预算充足）。
